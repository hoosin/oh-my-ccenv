# `ccenv stats` 技术文档

本文档详细描述 `ccenv stats` 命令的实现：数据来源、聚合逻辑、增量缓存。

---

## 1. 数据源：Claude Code 原生日志

`stats` 命令直接读取 Claude Code 产生的原始会话日志（默认路径为 `~/.claude/projects/**/*.jsonl`）。
如果你的日志存储在非标准位置，可以通过设置环境变量 `CCENV_LOG_DIR` 来覆盖默认路径。

**核心原则**：直接读取 CC CLI 的原始数据，与本地 Profile 配置无关。这保证了统计数据的真实性和客观性。

---

## 2. 聚合逻辑

### 2.1 默认维度：Model (模型)

默认情况下，`stats` 按 `message.model` 字段进行归类展示。

**名称清洗**：为了保证同型号模型能正确聚合，系统会自动过滤模型名称末尾的日期后缀（如 `-20251001`）。
*   例：`claude-haiku-4-5-20251001` -> `claude-haiku-4-5`

### 2.2 项目维度：Project (项目)

使用 `--project` 参数可以按项目目录名进行聚合。

---

## 3. 增量缓存机制

为保证在海量日志下的响应速度，系统使用 `~/.config/ccenv/stats.cache.json` 存储已解析的数据。
- **校验依据**：文件的 `mtime` 和 `size`。
- **追加解析**：文件增大时，仅从上次读取的偏移量开始解析新内容。

---

## 4. CLI 输出规范

### 4.1 数值格式化

所有数值列（`CALLS`, `INPUT`, `OUTPUT`）均采用易读的缩写格式：
*   **K**：千 (1,000)
*   **M**：百万 (1,000,000)
*   **B**：十亿 (1,000,000,000)

### 4.2 命令参考

| 参数 | 说明 |
| --- | --- |
| `--since <window>` | 时间窗口，如 `7d` (默认), `30d`, `YYYY-MM-DD` |
| `--project` | 按项目聚合（默认按模型聚合） |
| `--json` | 输出 JSON 格式数据 |

---

## 5. 性能与限制

- **损坏行处理**：自动跳过损坏的 JSON 行，不中断统计。
- **内存占用**：流式读取，单文件常驻内存极低。
